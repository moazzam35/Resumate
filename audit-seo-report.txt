3. ROOT CAUSE / PROBLEMS FOUND (real issues, not generic meta tags)
--------------------------------------------------------------------------------

  P1 — Canonical domain inconsistency (CRITICAL)
    robots.ts and sitemap.ts derived from SITE_CONFIG.url (env-driven), but the
    root layout hardcoded `metadataBase: new URL("https://resumate.ai")` and the
    structured-data component hardcoded "https://resumate.ai" everywhere. Two
    sources of truth for the domain meant canonical/OG URLs could disagree with
    the sitemap/robots URLs depending on environment.
    FIX: everything now derives from SITE_CONFIG.url (env NEXT_PUBLIC_APP_URL).
    .env.example documents that production must set the real domain.

  P2 — robots.txt blocked /_next/ (Google rendering)
    `Disallow: /_next/` blocks Next.js JS/CSS bundles. Google's own guidance is
    to never block CSS/JS needed to render pages; this can suppress JS-driven
    rendering and hurt indexing.
    FIX: removed /_next/ from disallow. Kept /api/, /dashboard/, /admin/ and
    added /resume/ and /cover-letter/ (private user content).

  P3 — Fake structured data: SearchAction to nonexistent /search
    The sitewide JSON-LD declared a WebSite SearchAction pointing to
    "https://resumate.ai/search?q=..." — but no /search route exists anywhere in
    the app. That is fabricated structured data.
    FIX: removed the SearchAction entirely.

  P4 — Duplicate product schemas
    Structured data emitted BOTH WebApplication (offer price "0") AND
    SoftwareApplication (AggregateOffer 0-29) for the same product — conflicting
    duplicate descriptions of one product.
    FIX: consolidated into a single SoftwareApplication with an AggregateOffer
    (0–29 USD, 3 offers) matching the real pricing plans.

  P5 — Blog articles had no Article structured data
    Blog posts are genuine articles (title, author, date, category, content) but
    emitted no Article/BlogPosting schema and no article:published_time.
    FIX: added Article JSON-LD (headline, description, image, datePublished,
    author, publisher, mainEntityOfPage) + og:published_time on every post.

  P6 — Root-layout canonical "/" inherited by all pages
    `alternates: { canonical: "/" }` in the root layout was inherited by any page
    that failed to define its own canonical — a canonical footgun that would
    silently point pages at the homepage.
    FIX: removed from root layout (homepage defines its own "/" explicitly).

  P7 — Invalid metadata field
    Root layout had `applicationSize: "1024x768"` (not a valid Next.js metadata
    field — junk output).
    FIX: removed.

  P8 — Soft-404 for unknown blog slugs (partially fixed)
    /blog/<unknown-slug> returned HTTP 200 while the client component rendered
    its own "Post not found" fallback. Added `notFound()` in the page component,
    so the real 404 boundary now renders (title "Page Not Found – Resumate",
    robots noindex,nofollow, canonical /404). Verified in a real browser: the
    rendered page shows the 404 UI. Note: Next.js 16 streams dynamic responses,
    so the HTTP status is 200 for streamed notFound responses (documented Next.js
    behavior: 200 for streamed, 404 for non-streamed); the page is noindex so it
    will not be indexed. This is a framework behavior, not app logic.

  NOT CHANGED (deliberately):
  - Unverifiable marketing claims already present (testimonials with real-company
    names, "10,000+ resumes created", "2,400+ five-star reviews", stats on the
    About page). Per instructions these were flagged, not fabricated or edited.
    Google quality guidance suggests they should be verified or softened.
  - Pricing inconsistencies between landing (Pro $14/$9, Executive $29/$19) and
    PLANS config (Pro $12, Enterprise $29) — pre-existing product data; flagged,
    not changed.
  - FAQPage schema was NOT added: Google's FAQ rich results are currently
    restricted to well-known authoritative government/health sites, so FAQPage
    markup would not be eligible; adding it would be low-value.
  - Contact email inconsistency (support@resumate.app vs support@resumate.com)
    — pre-existing, flagged only.

10. GOOGLE SEARCH CONSOLE READINESS (manual steps for you)
--------------------------------------------------------------------------------

  1. Deploy with NEXT_PUBLIC_APP_URL set to the real domain (e.g.
     https://resumate.ai). Everything (canonicals, sitemap, robots, OG, JSON-LD)
     derives from it — do not ship without it.
  2. Add the site to Google Search Console and verify ownership (DNS TXT or HTML
     file method — requires domain access, cannot be done from this codebase).
  3. Submit https://<domain>/sitemap.xml in GSC.
  4. After indexing starts, use GSC URL Inspection to request indexing of the
     homepage, /features, /templates, /blog, and a couple of articles.
  5. Confirm /robots.txt and /sitemap.xml are reachable on the deployed domain.
